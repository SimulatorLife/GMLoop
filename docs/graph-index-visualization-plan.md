# Graph Index Visualization Plan

## Summary

Add an interactive, browser-based visualization for the graph index produced by
`gmloop graph index`. The viewer renders nodes and edges from the SQLite-backed
graph database as a force-directed or hierarchical layout, supporting hover
tooltips, click-to-focus, zoom/pan, search-to-highlight, and edge-type
filtering. The implementation reuses the existing `@gmloop/semantic` graph query
API and exposes a new `graph visualize` CLI leaf command that exports the graph
data and opens a self-contained HTML file in the user's default browser.

### Design Principles

1. **Reuse proven tools** – lean on established, widely-adopted visualization
   libraries rather than building rendering from scratch.
2. **No new runtime dependencies for core workspaces** – the visualization is a
   static HTML artifact generated by the CLI; the semantic workspace stays
   dependency-free of any browser or visualization library.
3. **Self-contained output** – the generated HTML file bundles all JavaScript and
   CSS inline so it works offline without a dev server.
4. **Minimal blast radius** – the feature touches only the CLI command layer (a
   new leaf command) and a thin export helper in semantic. No changes to the
   parser, formatter, linter, or refactor workspaces.

## Visualization Library Evaluation

| Library | License | Bundle size | Interactive features | Maturity | Verdict |
|---|---|---|---|---|---|
| **D3.js** | ISC | ~280 KB min | Full control: zoom, pan, tooltips, force layout | 13+ years, industry standard | ✅ Best fit for self-contained HTML |
| **Cytoscape.js** | MIT | ~340 KB min | Graph-native: layouts, filtering, hover events | 10+ years, academic + industry | ✅ Strong alternative |
| **vis-network** (vis.js) | MIT/Apache-2.0 | ~450 KB min | Force layout, hover, clustering, hierarchical | 8+ years, widely used | ⚠️ Larger bundle, less flexible |
| **Sigma.js** | MIT | ~180 KB min | WebGL-accelerated large graphs | 5+ years | ⚠️ WebGL dependency, less tooltip control |
| **React Flow** | MIT | ~200 KB min | Drag, zoom, minimap | 4+ years | ❌ Requires React runtime |
| **Mermaid** | MIT | ~1 MB min | Static diagram rendering | 5+ years | ❌ Not interactive enough |

### Recommendation: D3.js (force-directed layout)

D3.js is the recommended library for the following reasons:

- **Zero framework requirement** – works with vanilla HTML/SVG, ideal for a
  self-contained single-file artifact.
- **Battle-tested force simulation** – `d3-force` provides collision, centering,
  charge, and link forces out of the box, well-suited for the graph-index
  topology of scripts, objects, resources, and their edges.
- **Built-in zoom/pan** – `d3-zoom` handles multi-touch and scroll-wheel
  interactions.
- **Fine-grained control** – unlike opinionated libraries, D3 gives full control
  over tooltips, node styling by kind, edge coloring by type, and click behavior
  without fighting a framework's abstractions.
- **Small footprint** – only `d3-force`, `d3-selection`, `d3-zoom`, and
  `d3-scale` are needed (~60 KB combined when tree-shaken), but even a full D3
  UMD bundle at ~280 KB is acceptable for a one-time generated file.
- **Enormous ecosystem** – thousands of examples, tutorials, and StackOverflow
  answers for every conceivable graph layout question.

Cytoscape.js is a valid alternative if graph-native operations (shortest path,
clustering, compound nodes) become important later. The initial implementation
should use D3 and can be re-evaluated if requirements evolve.

## Architecture & Ownership

### Workspace responsibilities

| Workspace | Role | Changes |
|---|---|---|
| `@gmloop/semantic` | Exports a new `exportGraphVisualizationData()` function that queries all nodes and edges from the SQLite database and returns a typed JSON payload. | New file: `src/semantic/src/graph-index/export-visualization-data.ts` |
| `@gmloop/cli` | Adds a `graph visualize` leaf command that calls the semantic export, renders a self-contained HTML string, writes it to disk, and optionally opens the browser. | New handler in `src/cli/src/commands/graph.ts` |
| All others | No changes. | — |

### Data flow

```
SQLite DB ──► semantic.exportGraphVisualizationData() ──► JSON payload
    ──► CLI graph visualize ──► self-contained HTML file ──► browser
```

The semantic layer provides the data. The CLI layer owns the HTML template and
D3 embedding. This keeps the semantic workspace free of browser/visualization
dependencies and the CLI as the single owner of user-facing output artifacts.

## Data Model for Visualization Export

The semantic export function returns a typed payload that the CLI embeds as
inline JSON inside the HTML file:

```typescript
/** Payload embedded in the visualization HTML as inline JSON. */
type GraphVisualizationData = Readonly<{
    generatedAt: string;
    graphs: ReadonlyArray<{
        edgeCount: number;
        graphId: GraphIndexScope;
        nodeCount: number;
        rootPath: string;
    }>;
    edges: ReadonlyArray<{
        source: string;   // from_id
        target: string;   // to_id
        type: GraphEdgeType;
    }>;
    nodes: ReadonlyArray<{
        displayName: string;
        graphId: GraphIndexScope;
        id: string;
        kind: GraphNodeKind;
        name: string;
        snippet: string;
        summary: string;
    }>;
    projectRoot: string;
}>;
```

This is a denormalized, visualization-ready projection. It excludes large fields
(full file content, embedding vectors) and includes only what the renderer needs.

## Interactive Features

### Node rendering

- Nodes are rendered as SVG circles (or icons) colored by `kind`:
  - `script` → blue
  - `object` → green
  - `enum` → purple
  - `macro` → orange
  - `resource` / `sprite` / `shader` / `room` → gray variants
  - `file` → light gray
- Node radius scales with edge degree (more connections → larger node).
- Nodes belonging to the `toolset` graph use a dashed stroke to distinguish them
  from `project` nodes.

### Edge rendering

- Edges are rendered as SVG lines colored by `type`:
  - `calls` → solid blue
  - `references` → dashed gray
  - `contains` / `defines` → dotted green
  - `inherits` → solid red
  - `uses_toolset` → dashed orange
  - `depends_on` → solid gray
  - `placed_in_room` → dotted purple
- Arrowheads indicate direction.

### Hover tooltip

- Hovering over a node shows a tooltip with:
  - `displayName`
  - `kind`
  - `graphId`
  - `summary` (truncated to ~200 chars)
  - Edge count (incoming / outgoing)
- Hovering over an edge shows the edge type and the names of the connected
  nodes.

### Click-to-focus

- Clicking a node highlights its immediate neighborhood (all directly connected
  nodes and edges) and dims everything else.
- Clicking the background resets the view.
- Double-clicking a node pins/unpins it from the force simulation.

### Zoom and pan

- Scroll-wheel zooms in/out (via `d3-zoom`).
- Click-and-drag on the background pans the view.
- A "reset zoom" button restores the default viewport.

### Search-to-highlight

- A search input field at the top of the page filters nodes by `name` or
  `displayName` (case-insensitive substring match).
- Matching nodes are highlighted; non-matching nodes and their unrelated edges
  are dimmed.
- Pressing Escape or clearing the input restores the full view.

### Edge-type filtering

- A sidebar or toolbar with checkboxes for each `GraphEdgeType` value.
- Unchecking a type hides all edges of that type and removes orphaned nodes that
  have no remaining visible edges (unless they match the current search).

### Graph scope toggle

- A toggle or dropdown to show: `project` only, `toolset` only, or both.
- Defaults to both when a toolset graph exists, project-only otherwise.

### Legend

- A small legend panel showing the color/shape mapping for node kinds and edge
  types.

### Performance guardrails

- For graphs with more than 2,000 nodes, show a warning and offer to apply an
  automatic filter (e.g., hide `file` nodes, show only nodes with ≥ 2 edges).
- The force simulation uses `d3-force` with `alphaDecay(0.02)` and
  `velocityDecay(0.3)` for fast convergence on medium graphs.
- Node labels are hidden at low zoom levels and revealed progressively as the
  user zooms in, reducing SVG text rendering cost.

## CLI Command Design

### `graph visualize`

```
gmloop graph visualize [options]
```

| Option | Type | Default | Description |
|---|---|---|---|
| `--path <path>` | string | cwd | Project path |
| `--config <path>` | string | `gmloop.json` | Config file path |
| `--database-path <path>` | string | `.gmloop/graph.db` | SQLite database path |
| `--toolset-root <path>` | string | — | Optional toolset root |
| `--output <path>` | string | `.gmloop/graph.html` | Output HTML file path |
| `--open` | boolean | `true` | Open the file in the default browser |
| `--rebuild` | boolean | `false` | Force a graph-index rebuild first |

### Behavior

1. Resolve the project root and config (same as other graph commands).
2. Ensure the graph database exists (build if `--rebuild`, error if missing).
3. Call `Semantic.exportGraphVisualizationData(...)` to get the JSON payload.
4. Render the self-contained HTML string by interpolating the JSON payload into
   an HTML template that includes inlined D3 code and CSS.
5. Write the HTML file to `--output`.
6. If `--open` is set, use `node:child_process` `exec` to open the file with the
   platform's default browser (`open` on macOS, `xdg-open` on Linux, `start` on
   Windows).
7. Print a summary to stdout (or JSON envelope with `--json`).

## HTML Template Structure

The generated HTML file is a single self-contained document:

```
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="utf-8" />
  <title>GMLoop Graph Index – {{ projectRoot }}</title>
  <style>/* inline CSS for layout, tooltips, legend, controls */</style>
</head>
<body>
  <header>
    <h1>Graph Index: {{ projectRoot }}</h1>
    <input type="search" id="search" placeholder="Search nodes…" />
    <div id="filters"><!-- edge-type checkboxes --></div>
    <div id="scope-toggle"><!-- project / toolset / both --></div>
    <button id="reset-zoom">Reset Zoom</button>
  </header>
  <main>
    <svg id="graph"></svg>
    <div id="tooltip" class="hidden"></div>
    <aside id="legend"><!-- node kind + edge type legend --></aside>
  </main>
  <script>
    // Inline D3 UMD bundle (or d3-force + d3-selection + d3-zoom + d3-scale)
  </script>
  <script>
    const DATA = {{ jsonPayload }};
    // Force simulation setup, rendering, interaction handlers
  </script>
</body>
</html>
```

The D3 library code is inlined as a minified UMD script block so the file works
completely offline. The graph data is injected as a `const DATA = ...;` literal.

- `exportGraphVisualizationData` returns the correct shape from a test database
  with known nodes and edges.
- Empty databases produce a valid payload with zero nodes and edges.
- Nodes exclude embedding vectors and large internal fields.
- Edge records map `from_id`/`to_id` to `source`/`target` correctly.
- The `graphs` summary array reflects the graphs present in the database.

- The generated HTML contains the expected `DATA` variable with valid JSON.
- The generated HTML contains the D3 script block.
- `--output` writes to the specified path.
- `--json` output envelope matches the standard graph command shape.
- Missing database produces a clear error message.

### Manual / visual verification

- Open the generated HTML in Chrome, Firefox, and Safari.
- Verify zoom, pan, hover, click-to-focus, search, and edge-type filtering.
- Verify the legend renders correctly.
- Verify the toolset toggle works when a toolset graph is present.
- Verify the performance guardrail warning appears for large graphs.

### Phase 1: Data export (semantic)

  `src/cli/src/commands/graph.ts`.

  `src/cli/src/commands/graph-visualize-template.ts` that:
  - Embeds the minified D3 bundle inline.
  - Embeds the graph data as a JSON literal.
  - Includes all CSS and interaction JavaScript inline.
- Add CLI tests for command registration and output file generation.

### Phase 3: Interactive polish

- Refine the D3 force layout parameters for common graph sizes (50–2000 nodes).
- Add progressive label rendering based on zoom level.
- Add the performance guardrail for large graphs.
- Manual cross-browser testing.

## Assumptions and Defaults

- The visualization is a **read-only, offline artifact** – it does not start a
  dev server or require a network connection.
- D3.js is inlined as a UMD bundle inside the generated HTML. The CLI workspace
  does not add D3 as a Node dependency; instead, the minified D3 source is
  stored as a static asset string or fetched once at build time and cached.
- The default output path is `.gmloop/graph.html`, co-located with the SQLite
  database.
- The `--open` flag defaults to `true` for developer convenience.
- The visualization does **not** provide editing or mutation capabilities – it is
  purely a read-only inspection tool.
- No changes to the MCP workspace are required in the initial implementation.
  The `graph visualize` command can be exposed as an MCP tool automatically
  through the existing CLI-to-MCP catalog mechanism.

## Future Considerations

- **Cytoscape.js migration**: If compound nodes (e.g., grouping scripts inside
  objects) or advanced graph algorithms (shortest path, clustering) are needed,
  evaluate switching from D3 to Cytoscape.js.
- **Live mode**: A `--watch` flag that rebuilds the graph and refreshes the
  browser on file changes using a lightweight WebSocket dev server.
- **Subgraph extraction**: A `--focus <nodeId>` flag that pre-filters the
  visualization to show only a node's N-hop neighborhood, useful for large
  projects.
- **Export to other formats**: Support exporting the graph data as DOT
  (Graphviz), GEXF (Gephi), or CSV for use with external tools.
- **MCP resource**: Add a `gm://graph/visualization` resource that returns the
  HTML content for embedding in MCP-aware editors.
